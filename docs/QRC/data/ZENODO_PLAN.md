## Left out: recomputable feature matrices

Feature files of kind "features (recomputable from trace)" are excluded when they are a pure function of a raw FID trace in the same directory: `X = |FFT(fids_H, axis=1)|[:, bins]` (the standard 653-bin FID-spectrum readout, SOP). The bin selection (`bins`, top-653 of the first step's spectrum of the base arcsin / gain pass) is archived as a sidecar `<stem>.bins.npy` next to the file it came from; learned-encoding features (`X_learned.npz`) reuse the bins of their base pass (`X_arcsin` for `learned_seed*`, `design_c1/g<g>/X` for `design_learn/g<g>_seed*`). Rebuild after extracting:

```
python tools/qrc_zenodo_package.py --regen-features artifacts --plan tools/ZENODO_PLAN.json
python tools/qrc_zenodo_package.py --regen-features artifacts --plan tools/ZENODO_PLAN.json --only 'qrc_runs/realworld/santafe/*'
```

NumPy only (no GPU). The traces are stored complex64 while `X.npz` / `X_arcsin.npz` were computed from the complex128 pass, so rebuilt values agree to float32 precision (relative ~1e-7 measured), not bit-for-bit: their SHA-256 will differ from the manifest. `--check` compares against originals where they exist.

## Build / upload

```
python scripts/qrc_zenodo_package.py --build D:/zenodo_out --part-gb 10   # tar per record + README + SHA256SUMS
python scripts/qrc_zenodo_package.py --upload D:/zenodo_out --sandbox      # test on sandbox.zenodo.org first
python scripts/qrc_zenodo_package.py --upload D:/zenodo_out                # drafts on zenodo.org (never published)
```

`--build` needs about the packaged size free on the output drive. `--upload` reads the token from the environment variable `ZENODO_TOKEN` (scope deposit:write), refuses while `ZENODO_METADATA.json` still contains `TODO`, and leaves every deposition as an unpublished draft; review and publish on the Zenodo web UI.
